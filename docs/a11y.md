# chattea-web 웹 접근성 점검

브랜치: `chore/a11y-lighthouse` · 대상: `apps/chattea-web` (커뮤니티 페이지, Vite+React SSR), `apps/shell`, `apps/chattea-mobile`

## 스캔 결과 (전수)

검사 항목: 시맨틱 태그, `img` alt, 버튼/입력 `aria-label`, 포커스 링, 키보드 탐색.

### 이미 준수

- `index.html`: `lang="ko"`, `<title>`, `viewport`에 `user-scalable=no` 없음
- `<main>` 랜드마크, 게시글 목록 `<ul>/<li>`
- 모든 클릭 요소가 `<button type="button">` (커스텀 div 클릭 핸들러 없음)
- FAB `aria-label="글쓰기"` (아이콘 전용 버튼)
- `img`·`input` 없음 → 해당 항목 해당 없음

### 수정한 위반/결함

| 항목         | Before                                    | After                                                                                       |
| ------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------- |
| 페이지 헤딩  | `<h1>` 없음 (`page-has-heading-one` 위반) | `<main>` 내부에 스크린리더 전용 `<h1>커뮤니티</h1>` (`srOnly` 스타일, 시각 변화 없음)       |
| 로딩 상태    | 일반 `div` → 스크린리더 미안내            | `role="status"`                                                                             |
| 에러 상태    | 일반 `div`                                | `role="alert"`                                                                              |
| 빈 목록 상태 | 일반 `div`                                | `role="status"`                                                                             |
| 포커스 링    | 브라우저 기본값 의존                      | `rowButton`/`retryButton`/`writeFab`에 `:focus-visible` 아웃라인 명시 (`2px solid #EC4899`) |

파일: `src/pages/community/ui/community-page.tsx`, `community-page.css.ts`, `post-list.tsx`

## 회귀 가드

- 정적 린트: `apps/chattea-web`, `apps/shell`에 flat eslint 설정(`eslint-plugin-jsx-a11y` recommended) 추가, `pnpm lint`로 강제. 현재 위반 0건.
- 런타임 검사: `@testing-library/react` + jsdom + `vitest-axe` 도입, `test/community-page.a11y.test.tsx`에서 로그아웃/목록/에러 3개 상태에 `toHaveNoViolations` 단언. jsdom은 `color-contrast`를 계산하지 못해 해당 룰만 비활성화함.
- RN: `apps/chattea-mobile`에 `eslint-plugin-react-native-a11y` `all` 프리셋 적용 (`has-accessibility-hint`만 off — hint는 선택 항목이고 라벨과 중복되는 힌트 강제는 안티패턴). `has-valid-accessibility-descriptors` 위반 1건(`comment-row` 롱프레스 신고)을 `accessibilityActions`/`onAccessibilityAction`으로 수정.
- 기존 마크업 단언(`test/community-page.test.tsx`)은 SSR 경로 검증용으로 유지.

## Lighthouse 측정

`apps/chattea-web/scripts/lighthouse.mjs`가 SSR dev 서버 기동 → Chrome 탐색 → `/community` 측정 → 리포트 저장까지 자동 수행.

```bash
pnpm --filter chattea-web lighthouse
```

Chrome 탐색 순서: 시스템 Chrome(`chrome-launcher`) → Playwright chromium → `~/Library/Caches/ms-playwright` 캐시 바이너리. 셋 다 없으면 아래 중 하나 설치:

```bash
# 둘 중 하나
brew install --cask google-chrome
pnpm --filter chattea-web exec playwright install chromium
```

참고: `vite preview`는 `<!--app-html-->` 플레이스홀더를 SSR로 채우지 못해 빈 페이지를 서빙하므로, 스크립트는 항상 dev 서버(`tsx src/app/server.ts`)를 띄워 측정한다.

- accessibility 감점 0건 (h1 누락 수정 이후 자동 검사 클린 확인).
- 측정 중 발견해 함께 수정한 결함:
  - 비인증 상태에서 SSR 로딩 마크업과 클라이언트 로그인 화면이 달라 hydration mismatch 콘솔 에러 발생 → `useSyncExternalStore`로 첫 클라이언트 렌더를 SSR 출력과 일치시켜 해소 (`community-page.tsx`).
  - `<meta name="description">` 누락 → `index.html`에 추가.
- 잔여 감점(performance): dev 서버 미압축 번들 기준 `unminified-javascript`, `unused-javascript`, `cache-insight` — dev 모드 한계로 간주.
- 리포트 원본은 `apps/chattea-web/.lighthouse/`에 json+html로 저장 (gitignore 처리됨).
